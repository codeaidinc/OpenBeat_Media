# セキュリティノート — OpenBeat Media（無料OSS版）

OpenBeat Media は、ローカル専用の編集ツール（Studio, Python/Flask）と静的サイト生成器です。個人データ・Cookie・トラッカー・AI・外部呼び出しを既定で持ちません。以下は運営者・レビュア向けのセキュリティ留意点です。

## 1. Studio の secret_key（旧：ハードコード既定値）
- `studio.py` の `create_app()` は Flask の `secret_key` を環境変数 **`OPENBEAT_STUDIO_SECRET`** から取得します。
- **是正済み**：従来はハードコードの既定値 `"openbeat-studio-dev"` に依存していました。現在は環境変数による上書きが可能で、`OPENBEAT_STUDIO_PRODUCTION` を有効にした環境で `OPENBEAT_STUDIO_SECRET` 未設定の場合は **起動を拒否（RuntimeError）** します。
- 既定値は **localhost 専用の開発用フォールバック**であり、ソースに公開済みのため秘密ではありません。
- secret_key は flash メッセージの署名にのみ使用され、Studio は認証・個人データを扱いません。
- **運用指針**：Studio は `127.0.0.1`（ローカルホスト）にのみバインドして使用すること。公開ネットワーク／本番で動かす場合は `OPENBEAT_STUDIO_SECRET` にランダムな十分長い値を設定すること（本書には**秘密値を記載しない**）。

## 2. 記事本文の `| safe` レンダリング（XSS の前提）
- テーマ `themes/default/article.html` は記事本文を `{{ a.body_html | safe }}` で出力します（Markdown→HTML変換後）。
- これは **運営者が自分のコンテンツを執筆する前提**の設計です。本文には第三者からの入力（公開コメント・UGC・外部フォーム投稿）が入りません。
- したがって既定構成では信頼境界内であり、保存型XSSのリスクは限定的です。
- **注意**：運営者が外部・第三者由来のテキストを記事本文に貼り付ける運用に変える場合、`| safe` は信頼できない HTML をそのまま出力するため、**サニタイズ（許可タグのホワイトリスト等）を別途実装**するか、信頼できるソースのみ投入すること。
- Jinja2 のオートエスケープはテンプレート全体で有効（`select_autoescape(["html"])`）。`| safe` を明示した本文のみが例外です。

## 3. その他
- **出力先パス**：`OPENBEAT_CONTENT_DIR` / `OPENBEAT_OUTPUT_DIR` は運営者が制御。信頼できないパスを渡さないこと。
- **生成サイト**：静的HTML/CSSのみ。サーバサイドコード・Cookie・トラッカーなし。
- **デバッグモード**：`OPENBEAT_STUDIO_DEBUG` は開発時のみ。公開環境では無効にすること（スタックトレース漏えい防止）。
- **ネットワーク**：外部送信・テレメトリなし。
